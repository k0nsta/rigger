# rigger: TUI installer for personal setup repos

## Overview
- `rigger` is a public, generic Go/Bubble Tea tool. A user keeps their own (usually private) **setup repo** — `manifest.yaml`, Brewfiles, dotfiles, scripts — and rigger clones it with the machine's own credentials, shows what will be installed and linked, lets them pick, installs missing dependencies, links configs back to the repo and keeps several machines in sync.
- Problem it solves: restoring a machine is a README walk; configs drift into real copies; nothing finds missing tools or packages installed outside the Brewfiles; servers are set up by hand; one-off installer scripts live inside each dotfiles repo.
- Distribution: GitHub releases (darwin/linux × arm64/amd64) + `curl …/install.sh | sh` + a Homebrew cask in `k0nsta/homebrew-apps`. The setup repo never needs binaries.
- Use cases the design must cover (each is a profile in the user's manifest; profiles only preselect, every component and every Brewfile package can be toggled):
  - a second laptop used only as a remote client (terminal + remote-session helper + Claude Code, nothing else)
  - a personal Mac: most tools and apps, picked per package, adjusted later by rerunning rigger
  - a work Mac: a different set of tools and apps
  - a new Linux server: minimal tooling
- Decisions taken: Go + Bubble Tea v2; bootstrap = copy `~/.ssh` (or have a token), install rigger, `rigger init <repo>`.

## Context (from discovery)
- Code so far: `cmd/rigger` (version), `internal/manifest` (schema v1, load, validation, `@profile` expansion, `GroupOrder`) with tests; `example/` setup repo that validates; goreleaser/CI/release workflows copied from `k0nsta/agterm-remote` (casks with quarantine removal).
- First real setup repo: `k0nsta/machine-setup` (private) — grouped Brewfiles, framework-free zsh, `~/.claude` linked as a whole directory, agterm config, seeds with `${VAR}` secrets.
- Constraints found while designing against it:
  - apps in `/Applications` and fonts in `~/Library/Fonts` are often installed outside brew; cask install must not fail on them.
  - files tools rewrite (codex `config.toml`, colima `colima.yaml`, configs holding tokens) cannot be symlinks: they are seeds.
  - `brew bundle` honours `HOMEBREW_BUNDLE_{BREW,CASK,TAP,MAS}_SKIP` (checked in the Homebrew source) — per-package picks need no temp Brewfile.
  - Debian names: `batcat`, `fdfind`; a bare VPS may have neither git nor rsync.
  - Claude Code on Linux writes `~/.claude/.credentials.json`; `gh` on keyring-less Linux writes the token into `~/.config/gh/hosts.yml` — `sync` must never commit those.
  - agterm keeps app settings and window/workspace layouts in `~/Library/Application Support/agterm/` (`settings.json`, `windows.json`, `windows/<uuid>.json`).
- Toolchain: Go 1.27, `charm.land/bubbletea/v2` v2.0.10 (`tea.ExecProcess` releases the terminal for a child), `charm.land/lipgloss/v2`, `charm.land/bubbles/v2`, `gopkg.in/yaml.v3`, testify.

## Solution Overview
- **Manifest-driven**: the setup repo's `manifest.yaml` lists components; rigger knows only action kinds (link, seed, brew, apt, cmd, layouts). Adding a tool or config is a YAML edit in the user's repo.
- **Probe → review → apply**: every run probes the machine read-only; the TUI shows per-component status; the user toggles components and packages, resolves conflicts (adopt/keep), enters missing secrets, confirms, watches the run. `--dry-run` stops after the plan.
- **Pick at two levels**: components, and inside a Brewfile component its formulae/casks. Unpicked packages are saved per host (`exclude_packages`) and passed as `HOMEBREW_BUNDLE_*_SKIP`; profiles can carry default excludes.
- **Dependencies are found, not assumed**: `requires` pulls missing prerequisites in ("needed by X"); a `requires` on a component excluded for this platform is dropped, so `zsh: requires [core-cli, linux-core]` works on both.
- **Back-binding**: symlinks into the setup repo, seeds tracked by last-render hash, repo `origin` on SSH, the selection saved in `hosts/<name>.yaml` (tracked in the setup repo).
- **Multi-machine sync**: `rigger sync` = review local changes → commit chosen files → gitleaks gate → `pull --rebase` → re-apply the saved selection (template updates reach seeds) → drift report → push.
- **Remote**: `rigger remote <host>` installs rigger on the host with the public installer, clones the setup repo there with a forwarded agent, then runs the TUI over `ssh -t`.

## Technical Details

### Commands
| command | does |
|---|---|
| `rigger init <git-url> [--dir D] [--no-run]` | clone the setup repo (default dir `~/<git-host>/<repo-name>`, e.g. `~/github.com/machine-setup`), remember it, run the TUI |
| `rigger` | TUI for the remembered repo |
| `rigger apply [--profile P] [--only a,b] [--yes] [--dry-run]` | non-interactive apply |
| `rigger status` | table of components, exit 1 when a selected one is not ok |
| `rigger sync [--yes]` | commit/pull/re-apply/push |
| `rigger remote <ssh-host> [--profile P]` | set up a remote host |
| `rigger layouts export\|import <host>` | agterm-style layout snapshots |
| `rigger validate [dir]` | validate a setup repo (CI for setup repos) |
| `rigger version` | version |
Common flags: `--repo D` (or `RIGGER_REPO`), `--host NAME`.

Repo discovery order: `--repo`, `RIGGER_REPO`, current dir (or a parent) with `manifest.yaml`, the remembered path in local state.

### Clone credentials (`init`)
- System `git` with the user's SSH keys / credential helper; `GIT_TERMINAL_PROMPT=0` so failures are fast.
- If an HTTPS URL fails with auth, rigger asks once for a token (masked) and passes it through a one-shot `GIT_ASKPASS` helper; the token is never written to disk or to the remote URL. Afterwards `origin` is switched to SSH when the user has a key.
- On macOS without git (no Command Line Tools), `init` says so and runs `xcode-select --install`.

### Setup repo contract (documented in `docs/setup-repo.md`)
```
manifest.yaml        # required, version: 1
hosts/<name>.yaml    # written by rigger: profile, components, exclude_packages, ignore_packages
<anything else>      # Brewfiles, dotfiles, scripts referenced by manifest.yaml
```
```yaml
version: 1
groups: [base, packages, shell]          # optional display order; enforced when present
profiles:
  laptop:
    components: [homebrew, core-cli, zsh]
    exclude_packages: [some-cask]
  work:
    components: ["@laptop", work-tools]  # "@name" expands another profile
    exclude: [apps]
unmanaged: [docs, scripts]               # top-level dirs that are not configs
components:
  - id: zsh
    title: zsh
    group: shell
    platforms: [darwin, linux]           # empty = all
    requires: [core-cli, linux-core]
    brewfile: brew/core.Brewfile
    apt: [zsh]
    links:   [{src: zsh/.zshrc, dst: ~/.zshrc}]
    seeds:   [{src: tool/config.toml, dst: ~/.config/tool/config.toml, secrets: [TOOL_TOKEN]}]
    layouts: {src: agterm-app/layouts, dst: "~/Library/Application Support/agterm"}
    cmds:    [{name: plugins, check: test -d ~/.zsh/plugins, run: zsh/install-plugins.sh, sudo: false, tty: false, secrets: []}]
manual:
  - {path: ~/.ssh/config, note: copy by hand}
```
Validation (`rigger validate`, also on every load): schema version, unique ids, groups, platforms, every `src`/`brewfile`/repo script exists (layouts dir may not exist yet), `requires`/profile ids exist, no cycles, no link/seed/layouts `dst` inside another link's `dst`, every top-level dir used by a component or listed in `unmanaged`.

### Action probes and statuses
| action | probe (read-only) | statuses |
|---|---|---|
| link | `lstat dst`, compare | `ok`, `missing`, `conflict` (other link/dir or identical file → backup + link), `differs` (real **file** with other content → review asks adopt-into-repo or keep-repo; directories are always backup + link with a diff summary), `dangling` (dst links into the repo, src gone; reported, never removed) |
| seed | render src (only listed `secrets`; other `${...}` untouched), compare with dst and the last-render hash | `ok`, `missing`, `update` (live == last render, template changed → re-render), `both-changed` (diff, overwrite/keep), `local-edit` (only live changed → ok), `needs-secret` |
| brew | parse `brew`/`cask`/`tap` lines in Go; diff with one `brew list --formula -1` and one `brew list --cask -1`; one batched `brew info --cask --json=v2 <missing>` checks `app`/`font` artifacts on disk | `ok`, `N to install`; casks already on disk = `present (not brew-managed)`, counted as ok |
| apt | `dpkg-query -W` | `ok`, `N to install` |
| cmd | `check` exit code (no check = always run) | `ok` / `todo` |
| layouts | snapshot dir for this host, target `windows.json` | `ok`, `no-snapshot`, `fresh-target` (import offered) |

- Brew apply: `brew bundle install --file <Brewfile>` with `HOMEBREW_BUNDLE_{BREW,CASK,TAP}_SKIP` = excluded + present-outside-brew packages; no `--adopt`.
- Backups: `~/.local/state/rigger/backups/<timestamp>/<path-relative-to-HOME>`; nothing is deleted; deselecting a component removes nothing.

### Layouts
- generic: `layouts: {src, dst, files: [globs relative to dst], process: <app>}`; export copies matching files to `<src>/<host>/` with the home path (plain and JSON `\/`-escaped) replaced by `{{RIGGER_HOME}}`; `sync` exports.
- import only when the target has no `windows.json` yet, or on explicit `rigger layouts import <host>`; the user picks the host; placeholder → `$HOME`; existing files backed up; refused while `process` runs (`pgrep -x <process>`).

### Local state (untracked)
- `~/.config/rigger/state.yaml`: `repo` (path), `host` (asked once; default short hostname; `--host` overrides — macOS hostnames change with MDM/network), `seeds: {dst: sha256-of-last-render}`.
- `~/.config/rigger/secrets.env`: `KEY=value`, 0600; a value starting with `op://` is resolved with `op read`. The review screen asks (masked) for missing secrets of selected seeds/cmds.

### Apply engine
- Topological order; one component at a time; a failure marks dependents `skipped (needs X)`, others continue.
- Children: stdin `/dev/null`, `NONINTERACTIVE=1`, `GIT_TERMINAL_PROMPT=0`, `RIGGER_REPO`, PATH prefixed with `/opt/homebrew/bin:/usr/local/bin:~/.local/bin:~/go/bin`; cmd `secrets` exported from the secrets file.
- sudo: when any selected step needs it, one `sudo -v` via `tea.ExecProcess` before the run screen (plain in `apply --yes`), refreshed with `sudo -n -v` every 60 s; apt is one batched `sudo -n apt-get install -y …`. Only `tty: true` cmds use `tea.ExecProcess`.
- Events (`started`, `line`, `done`, `failed`, `skipped`) on a channel; the TUI turns them into messages, `apply --yes` prints lines.
- After success: `origin` switched to SSH if HTTPS; `hosts/<name>.yaml` written.

### Sync
1. Review `git status --porcelain` (tracked files changed by tools or the user + `hosts/<name>.yaml` + layout snapshots); the user picks files; explicit `git add <files>`, never `-A`.
2. Gate: `gitleaks protect --staged` when gitleaks is installed, else a built-in check for well-known credential files (`.credentials.json`, `hosts.yml` with `oauth_token`, `*.pem`, `id_*`); any hit aborts.
3. Commit `sync(<host>): <files>`; `git pull --rebase` (no autostash); on conflict `git rebase --abort` and stop.
4. Re-probe the saved selection → new links/packages, seed `update` go through review/apply.
5. Drift: `differs` link files (adopt/keep), `dangling` links, brew strays (`brew leaves` + casks not in any Brewfile, minus `ignore_packages`) → add to a chosen Brewfile or ignore.
6. Push.

### Remote
1. `ssh host 'command -v rigger || curl -fsSL …/install.sh | sh'` (needs curl; else `sudo apt-get install -y curl` first).
2. `ssh host 'command -v git || sudo apt-get install -y git'`.
3. `ssh -A host 'rigger init <origin-ssh-url> --no-run'` — agent forwarding only for this step.
4. `ssh -t host rigger --profile <P>` (default `server`, no `-A`).
5. If agterm is installed locally: `agtermctl terminfo install <host>`.
