# Per-machine variables

## Overview
- A setup repo's paths are the same on every machine today. The person keeps code in `~/code` on `laptop` and in `~/github.com` on other machines, so the setup repo's `tool-bus` (`git clone … ~/github.com/tool`) made a second clone on `laptop` beside the working one, and Claude now loads the `the plugin` plugin from it (2026-10-28).
- `vars:` in `manifest.yaml` gives defaults; `vars:` in `hosts/<name>.yaml` overrides them for that machine. rigger exports them into `cmds` (`check` and `run`) and expands `${NAME}` in a link's, seed's or layout's `dst`. `rigger status` shows the values in force and where each comes from.
- A linked file shared by every machine (e.g. `claude/settings.json`) keeps one path: a stable one (`~/.local/share/tool`) that a cmd links to `"$CODE/tool"` on each machine (Post-Completion).

## Decisions
- Per-machine variables in rigger, chosen over a symlink on `laptop` or one layout on every machine (decide panel, 2026-10-28).
- Vars reach cmds through a `Command.Env` field set by the engine, not through the session's exec environment, so `git`, `brew` and `op` children do not see them.
- Lands on one branch, `v0.1.3`, together with `docs/plans/20261112-public-fixes.md` (2026-11-12): this plan runs first, then that one on the same branch; one PR, one release.
- `sync` warns when a linked file's change replaces a tracked `~/` path with this machine's absolute home path, so it can be left out of the commit (2026-11-12; from `docs/backlog/sync-misses-home-path-in-linked-file.md`).
- `Target` of a link, seed or layouts action becomes the expanded path in `~` form, so every display and hint (`rigger adopt <path>`) shows a path the person can type.
- A host override is checked when the host is known (session open, `SetHost`): names, values, and the nested/duplicate `dst` check on the merged paths.

## Solution Overview
- `Manifest.Vars` (defaults) and `HostFile.Vars` (overrides) merge in one session helper, called by `Open` and `SetHost`, into `action.Env.Vars` (`~` expanded) and a source per name for `status`.
- `Env.Expand`: `${NAME}` from `Vars`, then `~`. An unknown `${X}` stays literal (validation makes it unreachable); `$X` without braces is not expanded.
- `Command.Env` (`NAME=value` lines) set at engine.go:178, appended in `Probe` and `Apply` beside the secrets.
- `Session.Save` copies `Vars` from the loaded host file as it does `IgnorePackages`.
- A var change pulled from another machine moves the paths: the new link/seed shows as `missing` and is applied; the old one stays (rigger never uninstalls); a seed at a new path is a first render (`Local.Seeds` is keyed by the expanded `dst`, engine.go:163).

## Technical Details

### manifest.yaml and hosts/<name>.yaml
```yaml
# manifest.yaml
vars:
  CODE: ~/github.com             # default for every machine

components:
  - id: tool-bus
    cmds:
      - name: tool checkout
        check: test -d "$CODE/tool"
        run: git clone git@github.com:example/tool "$CODE/tool"
      - name: tool link        # before the plugin step: settings.json names this stable path
        check: test "$(readlink ~/.local/share/tool)" = "$CODE/tool"
        run: mkdir -p ~/.local/share && ln -sfn "$CODE/tool" ~/.local/share/tool
```
```yaml
# hosts/laptop.yaml (rigger keeps vars: when it rewrites the file)
profile: personal
vars:
  CODE: ~/code
```

### status
```
laptop · darwin · profile personal · repo ~/setup
vars: CODE=~/code (hosts/laptop.yaml)
```

### Validation
- name: `[A-Z][A-Z0-9_]*`, not reserved: `HOME`, `PATH`, `USER`, `SHELL`, `TMPDIR`, `NONINTERACTIVE`, `RIGGER_*`, `SUDO_*`, `HOMEBREW_*`, `GIT_*`
- value: `~`, `~/…` or absolute; no `${…}`
- `${NAME}` in a `dst` with no `NAME` in the manifest's `vars:` → `component tool-bus: links: ${CODEDIR} is not in vars`
- a name also used as a seed's or cmd's secret → error
- host overrides: the same name and value rules plus the nested/duplicate `dst` check on the merged paths, at session open and `SetHost`; a host var the manifest does not declare → warning in `status` only (`apply`, `sync`, the TUI say nothing)
- `rigger validate` sees only the manifest, so host overrides are checked by the commands that open a session
