# Per-machine variables

## Overview
- A setup repo's paths are the same on every machine today. The person keeps code in `~/Dev/github.com` on `mba` and in `~/github.com` on other machines, so `machine-setup`'s `agent-bus` (`git clone … ~/github.com/agentd`) made a second clone on `mba` beside the working one, and Claude now loads the `mm-agent` plugin from it (2026-10-28).
- `vars:` in `manifest.yaml` gives defaults; `vars:` in `hosts/<name>.yaml` overrides them for that machine. rigger exports them into `cmds` (`check` and `run`) and expands `${NAME}` in a link's, seed's or layout's `dst`. `rigger status` shows the values in force and where each comes from.
- A linked file shared by every machine (e.g. `claude/settings.json`) keeps one path: a stable one (`~/.local/share/agentd`) that a cmd links to `"$CODE/agentd"` on each machine (Post-Completion).

## Decisions
- Per-machine variables in rigger, chosen over a symlink on `mba` or one layout on every machine (decide panel, 2026-10-28).
- Vars reach cmds through a `Command.Env` field set by the engine, not through the session's exec environment, so `git`, `brew` and `op` children do not see them.
- `Target` of a link, seed or layouts action becomes the expanded path in `~` form, so every display and hint (`rigger adopt <path>`) shows a path the person can type.
- A host override is checked when the host is known (session open, `SetHost`): names, values, and the nested/duplicate `dst` check on the merged paths.

## Testing Strategy
- **unit (manifest)**: parse `vars:`; name rule; reserved names; value rule (`~`, `~/…` or absolute, no `${…}`); undeclared `${NAME}` in a `dst`; secret clash; nested/duplicate `dst` on default-expanded paths.
- **unit (app)**: `Session.Save` after `apply` and after a profile switch keeps `vars:`; `SetHost` re-merges (open as host A, `SetHost("mba")`, the mba override is in force); a bad host var (lower case, reserved, relative value) and an override that nests one `dst` in another are errors at open; a host var the manifest does not declare is a warning.
- **unit (action/engine)**: `Env.Expand` with `${CODE}` then `~`, an unknown `${X}` left literal, `$X` not expanded; a link/seed/layouts `dst` with `${CODE}` lands at the host's path; `Target` is the expanded `~` form; a cmd's `check` and `run` see `CODE` through the mock Runner (engine_test.go:45-60).
- **cli**: `rigger status` prints the `vars:` line and the undeclared-var warning; sync's replaced-link warning for a `${CODE}` link names the real path (`rigger adopt ~/Dev/x`).
- **e2e**: two machines, one with a host override: the same cmd creates `$CODE/marker` in each machine's own place; `status` shows each; the manifest gets `vars:` in the test (as `remoteFromExample` edits copies, e2e_test.go:93).

## Solution Overview
- `Manifest.Vars` (defaults) and `HostFile.Vars` (overrides) merge in one session helper, called by `Open` and `SetHost`, into `action.Env.Vars` (`~` expanded) and a source per name for `status`.
- `Env.Expand`: `${NAME}` from `Vars`, then `~`. An unknown `${X}` stays literal (validation makes it unreachable); `$X` without braces is not expanded.
- `Command.Env` (`NAME=value` lines) set at engine.go:178, appended in `Probe` and `Apply` beside the secrets.
- `Session.Save` copies `Vars` from the loaded host file as it does `IgnorePackages`.
- A var change pulled from another machine moves the paths: the new link/seed shows as `missing` and is applied; the old one stays (rigger never uninstalls); a seed at a new path is a first render (`Local.Seeds` is keyed by the expanded `dst`, engine.go:163).

## Technical Details

### manifest.yaml and hosts/<name>.yaml
```yaml
# manifest.yaml
vars:
  CODE: ~/github.com             # default for every machine

components:
  - id: agent-bus
    cmds:
      - name: agentd checkout
        check: test -d "$CODE/agentd"
        run: git clone git@github.com:k0nsta/agentd "$CODE/agentd"
      - name: agentd link        # before mm-agent: settings.json names this stable path
        check: test "$(readlink ~/.local/share/agentd)" = "$CODE/agentd"
        run: mkdir -p ~/.local/share && ln -sfn "$CODE/agentd" ~/.local/share/agentd
```
```yaml
# hosts/mba.yaml (rigger keeps vars: when it rewrites the file)
profile: personal
vars:
  CODE: ~/Dev/github.com
```

### status
```
mba · darwin · profile personal · repo ~/Dev/github.com/machine-setup
vars: CODE=~/Dev/github.com (hosts/mba.yaml)
```

### Validation
- name: `[A-Z][A-Z0-9_]*`, not reserved: `HOME`, `PATH`, `USER`, `SHELL`, `TMPDIR`, `NONINTERACTIVE`, `RIGGER_*`, `SUDO_*`, `HOMEBREW_*`, `GIT_*`
- value: `~`, `~/…` or absolute; no `${…}`
- `${NAME}` in a `dst` with no `NAME` in the manifest's `vars:` → `component agent-bus: links: ${CODEDIR} is not in vars`
- a name also used as a seed's or cmd's secret → error
- host overrides: the same name and value rules plus the nested/duplicate `dst` check on the merged paths, at session open and `SetHost`; a host var the manifest does not declare → warning in `status` only (`apply`, `sync`, the TUI say nothing)
- `rigger validate` sees only the manifest, so host overrides are checked by the commands that open a session
